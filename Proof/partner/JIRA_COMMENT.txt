Findings for the developers (Partner portal)

1. Server crash on a short GLN. A 7-digit BizLocation_GLN returns HTTP 500 "Internal server error" instead of a line error. Evidence: 2c, 2g.

2. Upload checks are weaker than on the Manufacturer portal. GTIN and GLN check digits are not checked at upload. A GLN with a bad check digit is accepted and stored, and an 11-digit GTIN is zero-padded before L5 rejects it. Evidence: 2b, 2d, 2e, 2f.

3. Rows are dropped while the upload reports success. Seen in 12a (100 rows, 99 stored), 16 (4 rows, 3 stored), 4b (10 rows, 8), 6b (8 rows, 5), 14c (3 rows, 2) and 21c (2 rows, 1). No line number is given. Evidence: those shots and their -status.

4. Events accepted for another organisation's location and product. The partner template is pre-filled with Test Manufacturer's GLN, and MEMPHIS uploads at that GLN are accepted with only an UNKNOWN_SGLN warning. KEMSA's GLN and the Xarelto GTIN are also accepted. Evidence: 1-status, 13d, 13d-status.

5. Placeholder serials become real serials. NULL and TBD were stored, and 0, NA and DUMMY already exist from the Manufacturer run. Evidence: 14b, 14c, 14d, 14f.

6. CSV shipping skips PPB approval. Packages built and shipped in the same file are never approved, and no NO_REGULATORY_APPROVAL flag is raised. Evidence: 8b-status, 9b-status.

7. API key handling. The dialog asks for a production key, but a sandbox key is accepted and every job runs as sandbox. An invalid key returns HTTP 400 with a 401 body. Evidence: 13f, any -status.
