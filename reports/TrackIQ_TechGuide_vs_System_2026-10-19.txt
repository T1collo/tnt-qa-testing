h3. TrackIQ Partner Technical Guide vs live system — agreement check (2026-10-19)

*Environment:* https://trackiq.apeiro-digital.com
*Guide checked:* {{/partners/docs}} (Partner Learning Center — Technical Guides + Test Execution, all four organisation types; content identical across types) and the Swagger at {{/api/partner-docs-json}}
*Endpoints exercised:* {{POST /api/integration/manufacturer/events}}, {{/supplier/events}}, {{/facility/events}}, {{/facility/events/dispense}} — sandbox keys
*Method:* every testable rule in the guide was turned into a live request (JSON-LD with short CBV tokens and EPCIS 1.2 XML where both apply), fresh identifiers on every request (registered product Amtel {{8904179.170218}}), setup chains (commission → pack → ship → receive …) where a rule needs history. 571 requests in total.

h4. Notable agreements

* TC-AUTH-02/03, §6.2 401 — Missing or invalid X-API-Key -> 401
* TC-AUTH-04, §2.5 "a Distributor key cannot submit Commissioning" — Role scope -> 403
* §1.3 permission matrix (core) — Commissioning manufacturer-only; packing not facility; unpacking distributor; dispensing facility-only; stock count not manufacturer
* TC-CON-01, §6.4 table — A resubmitted eventID -> 409 DUPLICATE_EVENT_ID
* §6.3 payload fingerprint — Same business content with a new eventID -> 409 DUPLICATE_EVENT_PAYLOAD
* §2.6, §3.3.3, Swagger — Dispense is sync 201; other events are async 202
* §2.4 / §2.6.3 "full urn:epcglobal:cbv:… values are rejected" in JSON-LD — Full URNs are rejected in JSON-LD
* §6.1.1 INVALID_XML_STRUCTURE — Malformed XML -> 400
* §6.1.1 FUTURE_EVENT_TIME (>5 min) — Future eventTime is rejected
* §2.6.3/§6.1.2 STALE_EVENT_TIME (>7 days) — Stale eventTime gives a warning (async)
* §6.1.1 INVALID_EXPIRY_FORMAT — Expiry must be YYYY-MM-DD
* §3.1.1 ILMD lotNumber + itemExpirationDate mandatory; action must be ADD — Commissioning field rules
* §2.6.3 mandatory eventID / eventTimeZoneOffset / bizLocation; eventTime needs a timezone — Missing core fields -> 400
* §6.1.1 INVALID_GS1_IDENTIFIER; GS1 lengths (SGTIN 13 digits + serial ≤ 20, SSCC 17, SGLN 12 + ext) — Malformed identifiers are rejected
* §6.1.1 DUPLICATE_EPC_IN_EVENT — Duplicate EPC in one event is rejected
* §2.6/§6.1.1 TOO_MANY_SERIALS (50,000) — More than 50,000 serials is rejected
* §6.2 207 PARTIALLY_ACCEPTED — Mixed document -> 207 with breakdown
* §2.7.5 IMPOSSIBLE_SENSOR_VALUES (min>max); §2.7.4 uom Rec 20 — Sensor bounds and units
* §6.4 error declarations — did_not_occur accepted; CONTENT_MISMATCH / ORIGINAL_NOT_FOUND / BEFORE_EVENT / CORRECTIVE_NOT_FOUND -> 400
* §6.1.2 flags EXPIRED_PRODUCT, EXPIRING_SOON — Past or near expiry at commissioning is flagged
* §6.1.2 SHIPPING_WITHOUT_COMMISSIONING, UNCOMMISSIONED_CHILD, RECEIVING_WITHOUT_SHIPPING (SGTIN), UNPACK_WITHOUT_AGGREGATION, UNKNOWN_SGTIN (async), UNKNOWN_SGLN, INVALID_LOT, NO_REGULATORY_APPROVAL — Advisory flags fire, event stored
* §3.1.4 / TC-MFG-06 INVALID_PARENT_CHILD_RELATION — Shipping a child SGTIN of an active SSCC is flagged
* §3.2.3 CHILD_ALREADY_AGGREGATED — Second parent is flagged
* §3.1.3 "Child SSCCs in in_transit cannot be packed" — Packing an in_transit SSCC is flagged
* Appendix B allowed transitions — active->in_transit->active, active->damaged, in_transit->damaged, active->expired, active/in_transit->stolen, damaged->destroyed, expired->destroyed, active->returned, returned->active
* Appendix B prohibited transitions; §3.1.4; §4.4.1 — damaged->in_transit, stolen->in_transit, dispensed->damaged/expired/in_transit, destroyed->any are flagged
* §4.1 Regulator approval forbidden for trading partners — Partner regulator approval is not honoured
* Happy path (TC-MFG-01/03/04/05, TC-DIS-01/05, TC-FAC-01/02) — Documented flow is accepted
* §3.3.3 / TC-FAC-03/04 / Swagger — Class-level, mixed and all-serialized dispense; dispense field validation
* §6.2 / Test Execution content types — application/ld+json and application/xml are accepted; others give 415
* Guide examples (fresh identifiers) — Docs examples are accepted
* §3.1.4 sourceList required; §2.2 LGTIN class identifiers — Shipping without sourceList is rejected; LGTIN quantityList is accepted

* §5-6 rate limits (manufacturer 5-10k, distributor 3-5k, facility 1k req/min; 429) — Rate limiting: Not tested; would need load testing (out of scope)
* §2.6 async max 10 MB / MESSAGE_SIZE_EXCEEDED at 10 MB — Async size limit: Not tested, to avoid a payload over 10 MB. 1.5 MB was accepted.
* §2.5 retention ≥3 years, immutability, audit logging, annual key rotation — Storage and governance: Not observable through the partner API
* §6.1.1 INVALID_GTIN/GLN/SSCC_CHECK_DIGIT — Check-digit rejects: EPC URNs carry no check digit, and a GS1 Digital Link URI is rejected as a non-URN before any check-digit test, so no input path triggers these codes
* §6.1.2 INACTIVE_SGLN — Inactive GLN flag: No known inactive SGLN in master data
* §4.3 recall effects, RECALL_ACTIVE, recalled->destroyed, recalled->dispensed prohibited, App B recall rows — Recall behaviour: No partner key may submit holding/recalled (403), so recalled state cannot be created
* §3.1.1.1 Lot Integrity / TC-MFG-02 MIXED_LOT_IN_COMMISSIONING — Mixed lots flagged: A single event carries one ILMD lot, so a mixed-lot event cannot be expressed; the test case is ill-defined
* §3.1.1 foreign MAH countryOfOrigin / foreign MAH GLN in sourceList — Import commissioning rules: No consequence documented, and the key's foreign/domestic status is unknown
* §4.1 "EPCs remain in quarantine until regulator approval" — Quarantine release: No regulator key. NO_REGULATORY_APPROVAL fires on almost every event for registered product (60 times in the chain run).
* §1.2 "Fragmented or partial messages will be rejected"; "Do not send intermediate OBSERVE events" — Message hygiene: No observable criterion
* §2.7 "sensor data not compatible with EPCIS 1.2 XML" — XML sensor rejection: The XML sensor test was rejected over the sensorReport type format, not as unsupported, so this is inconclusive
* §6.2 500/502/503/504 meanings; async outcome tracking in /partners/async — Infra and portal: Needs a portal login, and the async intake returns 503
* §4.4.1 damaged SSCC quarantines its children — Child quarantine: Only testable through dispense, which validates nothing (dispensing a child of a damaged SSCC -> 201 with no flag), so this is subsumed by the dispense findings
* Appendix C formatting (2-space indentation, @context as array, XML element order, nothing after the root) — Formatting guidance: Not enforced, and no consequence is documented: a string @context, out-of-order XML elements and content after the root were all accepted
